# BC-bot на Render Free

В этой версии `cloud:app` принимает события Telegram по HTTPS webhook. Запуск через `bot.py` оставлен для локального сервера с SQLite. Не запускай polling и webhook одновременно для одного бота.

## Создание сервиса

1. Источник: этот репозиторий, ветка `main`.
2. Тип: Web Service, Runtime: Python, тариф: **Free**.
3. Build: `pip install -r requirements.txt`.
4. Start: `gunicorn -c gunicorn.conf.py --bind 0.0.0.0:$PORT cloud:app`.
5. Environment: задай `GUNICORN_CMD_ARGS` пустой строкой, чтобы убрать стандартный preload Render. На этой версии нужен ровно один процесс: выбранная конфигурация обрабатывает события последовательно.

`APP_URL` можно не задавать: на Render используется документированная `RENDER_EXTERNAL_URL`. После заполнения настроек нажми **Save and deploy**. Бот сам устанавливает webhook на `<адрес сервиса>/telegram`, сохраняет очередь Telegram, задаёт отображаемое имя BC-bot и команды.

## База данных и бесплатность

На Free локальная файловая система Render временная: поэтому webhook-версия **не использует SQLite как запасной вариант**. Без `DATABASE_URL` бот остаётся в режиме ожидания настройки и не принимает материалы. Статусы `/health` и `/` показывают `bot_ready: false`, а `/ready` возвращает 503.

Можно подключить PostgreSQL у внешнего провайдера с бесплатным тарифом, если его условия подходят. У Render бесплатная PostgreSQL-база истекает через **30 дней**: это только временный тестовый вариант, не постоянное хранилище каталога. Не создавай её, рассчитывая на бессрочную бесплатную работу; заранее обеспечь резервную копию и перенос. Платные базы и диски не требуются кодом и не создаются автоматически.

Free web service засыпает после 15 минут без входящих запросов. Следующее событие Telegram разбудит сервис; ответ может задержаться из-за холодного старта. Не добавлены искусственные запросы для обхода сна.

## Проверка после запуска

- `/health` — жив ли HTTP-процесс; 200 не означает, что Telegram-бот настроен.
- `/ready` — настроен ли бот, webhook и соединение с базой на старте.
- Отправь боту `/start`, `/id`, затем администратором `/admin` и добавь тестовую карточку.
- Перезапусти сервис и проверь, что каталог сохранился.
- Токен, пароль БД и WEBHOOK_SECRET не должны попадать в исходники, скриншоты или сообщения.

Окончательно обработанные update_id сохраняются в PostgreSQL на 7 дней. При повторной доставке Telegram они не обрабатываются заново. Если процесс упал между отправкой ответа и записью update_id, ответ может повториться. Счётчики доставки не подтверждают успешное подключение VPN. Для больших каталогов и нагрузки нужна отдельная очередь и расширенное хранение.

Схема создаётся через `CREATE TABLE IF NOT EXISTS`; автоматического переноса данных из локальной SQLite в PostgreSQL нет. Для уже заполненного каталога нужен отдельный перенос. Ошибки и таймауты БД приводят к 503 и повторной доставке Telegram.
