# BC-bot — бесплатный Telegram-каталог

**Для Render Free используй [RENDER_SETUP.md](RENDER_SETUP.md).** Добавлена webhook-версия `cloud.py` с PostgreSQL: каталог сохраняется вне временной файловой системы Render. Ниже описан первоначальный локальный запуск через `bot.py` с SQLite. Токены и строки подключения задаются только в настройках хостинга.

Готовая основа бота на Python 3.11+ без сторонних Python-библиотек. Пользователи бесплатно получают опубликованные владельцем материалы. Красные кнопки разделов и «Назад», зелёные кнопки выдачи и публикации. Цвета и внешний вид отображает Telegram с учётом темы и версии клиента.

При `/start` бот приветствует человека по его имени из Telegram: «Привет, Анна! 👋», представляет BC-bot и показывает разделы с эмодзи. Имя безопасно экранируется и не сохраняется в базе. При возврате в меню приветствие также использует имя нажавшего кнопку. Кнопка поддержки ведёт к владельцу @N777NN52.

`BOT_NAME=BC-bot` задаёт имя в сообщениях и через `setMyName` — отображаемое имя бота в Telegram при запуске. Username самого бота (адрес `@...bot`) выбирается отдельно в BotFather. @N777NN52 — контакт владельца, он не используется для выдачи прав администратора: заполни числовой `ADMIN_IDS` по инструкции ниже.

## Возможности

- Разделы WARP, VPN-приложения, Telegram-прокси, DNS, новости, ИИ и другое.
- DNS и новости: публикация текстом, файлом или ссылкой. ИИ: каталог ссылок и приложений, без встроенного ИИ-чата; тарифы внешних сервисов задаются их владельцами.
- Выдача APK, ZIP, конфигов и других документов через Telegram file_id, а также HTTPS-ссылок.
- MTProxy и SOCKS5: проверка обязательных параметров ссылки и кнопка подключения.
- Личная админ-панель: пошаговая загрузка, предпросмотр, публикация, скрытие и восстановление.
- Красные кнопки «Назад», включая возврат по шагам загрузки с сохранением черновика.
- Поиск с поддержкой русских букв, избранное, новинки и страницы каталога.
- Жалобы «Не работает» с уведомлением администраторов, статистика выдач.
- SQLite: каталог, черновики, избранное и позиция polling сохраняются после перезапуска.
- Ограничение частоты запросов; админ-действия доступны только указанным ID и только в личном чате.
- Необязательные премиум-эмодзи в кнопках основных разделов.

Бот раздаёт материалы. Он не создаёт VPN-серверы, не подключает телефон к VPN самостоятельно и не проверяет работоспособность VPN-конфига или приложения. В архиве нет выдуманных «рабочих серверов»: каталог изначально пустой, его наполняет владелец.

## Первый запуск

1. Открой официальный **@BotFather** в Telegram, отправь `/newbot`, выбери имя и username. Скопируй выданный токен.
2. Узнай свой числовой Telegram ID. Если он пока неизвестен: поставь временно `ADMIN_IDS=1`, запусти бота, отправь ему `/id`, затем замени `1` на полученный ID и перезапусти. Не публикуй материалы до установки правильного ID.
3. Скопируй `.env.example` в `.env`. Заполни `BOT_TOKEN` и `ADMIN_IDS`. По желанию поменяй `BOT_NAME`, `SUPPORT_URL`.
4. В терминале из папки проекта выполни:

```sh
python3 bot.py
```

5. Открой своего бота → `/start`. Для управления — `/admin`.

Нужен доступ с компьютера/сервера к `api.telegram.org`. Сам бот не опубликован и не запущен разработчиком: для этого требуются твой токен и работающий хостинг. Токен держи в `.env`, не отправляй в публичные сообщения. При утечке перевыпусти его через BotFather.

## Как добавить материал

`/admin` → «Добавить материал» → раздел → название → описание → документ или ссылка → «Опубликовать бесплатно».

Можно переслать документ боту на шаге загрузки. Просто прислать файл вне этого сценария недостаточно: сначала нужно выбрать раздел и оформить карточку. В описание удобно включить платформу, страну, версию, дату проверки и краткую инструкцию.

Назад на каждом шаге возвращает к предыдущему. Сохранённые название и описание можно оставить кнопкой. На шаге материала после возврата пришли файл/ссылку повторно. `/cancel` отменяет черновик. После публикации карточка сразу появляется в каталоге.

Новости публикуются в разделе бота, без массовой рассылки. DNS-текст отображается как добавленный администратором; бот не проверяет доступность DNS и не меняет настройки телефона.

Через «Все материалы» администратор видит и скрытые карточки. «Скрыть» убирает их из публичного каталога и запрещает выдачу через старые кнопки. Жалоба сама по себе не скрывает материал; администратор проверяет его вручную. В данной версии редактирование опубликованной карточки выполняется через скрытие старой и добавление новой.

## Красные кнопки и премиум-эмодзи

Красные кнопки используют официальный `style: danger`. Обычные эмодзи включены сразу. В `.env` можно задать ID собственных эмодзи:

```dotenv
CUSTOM_EMOJI_IDS={"warp":"реальный_числовой_ID","vpn":"реальный_числовой_ID","proxy":"реальный_числовой_ID","other":"реальный_числовой_ID","dns":"реальный_числовой_ID","news":"реальный_числовой_ID","ai":"реальный_числовой_ID"}
```

Пример показывает формат: замени значения на настоящие числовые строки; не копируй заполнители как готовую настройку. ID — это `custom_emoji_id`, а не номер набора стикеров. Его можно получить из `entities` сообщения с custom emoji, пришедшего боту, или через Bot API. Список неизвестных ID бот сам не подбирает.

По документации Telegram: custom emoji в кнопках и сообщениях, отправленных ботом напрямую в личный/групповой чат, доступны при Premium у владельца бота; альтернативный вариант — бот, купивший дополнительные username на Fragment. В этой версии настроены иконки кнопок, а текст использует обычные эмодзи. Без необходимых прав оставь `CUSTOM_EMOJI_IDS={}`. Если неверный ID или права приводят к ошибкам Telegram, отключи настройку и перезапусти. Покупки или подписки бот не оформляет.

## Постоянная работа через Docker

На сервере с Docker Compose, из папки с заполненным `.env`:

```sh
docker compose up -d --build
docker compose logs -f
```

Остановить: `docker compose down`. Данные находятся в именованном томе `bot-data`; не удаляй его и не используй `down -v`, если хочешь сохранить каталог. Для обновления кода повтори `docker compose up -d --build`.

Для круглосуточной работы сервер должен оставаться включённым. На Android можно попробовать Python в Termux, но система может останавливать фоновые процессы; для постоянной работы удобнее сервер. Оплата хостинга, если она нужна, отдельно от бесплатного доступа к материалам.

Запускай **один экземпляр на один токен**. При уже установленном webhook бот остановится: сначала отключи прежний способ запуска, затем вызови `deleteWebhook` через Bot API, не сбрасывая очередь. Автоматически чужой webhook код не удаляет.

## Резервная копия и данные

Хранятся Telegram ID пользователей, дата первого взаимодействия, избранное, черновики администратора, жалобы и события выдачи. Сообщения пользователей вне поиска/админ-сценария не архивируются. Username и имена пользователей не сохраняются. Ссылки и конфиги, опубликованные владельцем, доступны всем пользователям бота; не добавляй личные ключи, которые не собираешься раздавать.

Для согласованной копии SQLite используй встроенный backup (при локальном запуске):

```sh
python3 -c "import sqlite3; a=sqlite3.connect('data/bot.sqlite3'); b=sqlite3.connect('backup.sqlite3'); a.backup(b); b.close(); a.close()"
```

Для Docker выполняй backup внутри контейнера и копируй результат командой `docker compose cp bot:/app/data/backup.sqlite3 ./backup.sqlite3`. Не копируй только основной SQLite-файл работающего бота без WAL-файлов. Для восстановления останови бота и восстанови БД из копии. file_id привязаны к исходному боту: при создании нового токена для другого бота документы потребуется загрузить заново.

## Проверки и ограничения

```sh
python3 -m unittest discover -s tests -v
```

Автоматические проверки используют поддельный Telegram API: загрузка и публикация, повторное нажатие, доступ администратора, скрытые файлы, поиск, жалобы, избранное и возврат по шагам. Настоящую отправку файлов, отображение кнопок, права Premium и развёртывание нужно проверить на твоём токене. Docker-конфигурация приложена, но образ в среде подготовки не запускался.

Это первая рабочая версия для одного процесса и небольшого каталога. Запросы обрабатываются последовательно. После сетевого обрыва или аварийного завершения отдельное сообщение может быть отправлено повторно; публикация черновика защищена от повторного нажатия. Счётчик выдач отражает отправленные файлы/ссылки, а не установку приложения или успешное VPN-подключение. Жалоба одного пользователя на одну карточку учитывается один раз; бот не сканирует APK на вредоносность.
